A backlog of recordings, transcribed by every machine you can spare.

SwarmScribe shares one big transcription job across many computers. A leader keeps the list of recordings and hands them out. Followers, on servers or ordinary PCs, each take a recording, transcribe it and send the text back.

In development. Not available yet.

How it works

  1. You mark what may be transcribed

    Only recordings you have explicitly cleared become jobs. Everything else stays where it is, and no follower can ask for it.

  2. Machines join with one command

    A follower needs Docker or Kubernetes and a join token. It uses a GPU if it finds one and falls back to the CPU if not.

  3. Each follower takes one recording at a time

    Followers call the leader and never accept incoming connections, so a PC behind a home router works as well as a server in a rack.

  4. Results land in your storage

    The leader stores every finished transcript in Azure Blob Storage, Google Cloud Storage or a local disk, whichever you already use.

The full transcript, ready to read, search or index.

Built to be left running

Nothing gets stranded
If a follower dies mid-job, its recording goes back in the queue. Every recording ends up either finished or parked with a reason.
Followers hold no keys
A follower never sees your storage credentials. It gets a short-lived link to one file, and nothing more.
The leader can be restarted any time
All state lives in Postgres, so any copy of the leader can stop without losing work.
Your hardware, your audio
Transcription runs on open Whisper models on machines you choose. No recording is sent to a transcription service.
You can see what is happening
Queue depth, each follower's throughput and every failure are visible without reading logs.
